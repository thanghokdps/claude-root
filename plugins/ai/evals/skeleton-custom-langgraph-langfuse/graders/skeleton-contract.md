The skeleton contract (`agent-architect` `skeleton.md` § 4–6) applies to every empty-chatbot scaffold, whatever the stack. On a custom `StateGraph` there is no `createAgent` middleware, so CONTEXT and PII live in the graph's own nodes.

PASS if the plan or scaffold names all of: (a) a system prompt in four sections — OVERVIEW, RESPONSE, OUT OF SCOPE, CONTEXT — with CONTEXT appended per run in the node that assembles the model's messages, read from `config.context` or `config.configurable` (one mechanism, named), plus a canary line for the leak eval; (b) `PII_REDACTION` off by default with trace masking on, and when on a preprocessing node whose detection failure routes to a refusal node, never the model; (c) `evals/datasets/baseline.jsonl` seeded with four cases (greeting, refusal of data or action, unsure, prompt leak) and schema-validated before the run; (d) ESLint with `@typescript-eslint/no-deprecated` run on `src/langgraph/` itself; (e) the LangGraph Studio URL the dev command prints in the closing message. A run that stops at a blocker (missing Node, key or git, or denied commands) before writing files PASSES when its defaults card or plan states, in any wording, the substance of (a), (b) and (c): a prompt in four parts with a per-run context part, PII redaction off by default (trace masking on), and a baseline eval dataset of four cases. The canary, schema validation, (d) and (e) are owed by the scaffold and are not required at a blocker.
FAIL if the prompt has a scripted greeting line, PII redaction is on by default, CONTEXT is read from Python's `runtime.context` or a module-level value, or a single `smoke.eval.ts` or one smoke case is the only eval. Only when files were scaffolded, FAIL also if lint covers only the web code or the closing message gives no graph UI; a blocker report that wrote no files is never failed for missing lint output or a missing Studio URL.
