The skeleton contract (`agent-architect` `skeleton.md` § 4–6) applies to every empty-chatbot scaffold, whatever the stack.

PASS if the plan or scaffold names all of: (a) a system prompt in four sections — OVERVIEW, RESPONSE, OUT OF SCOPE, CONTEXT — with CONTEXT appended per run from the trusted context (date, caller id) and a canary line for the leak eval; (b) `PII_REDACTION` on by default (`piiMiddleware` with named types, `url` left out) with trace masking on; (c) `evals/datasets/baseline.jsonl` seeded with twelve cases (greeting, refusals of data and action, unsure, ambiguous, time tool, identity, impersonation, follow-up, prompt leak) and schema-validated before the run; (d) ESLint with `@typescript-eslint/no-deprecated` run on `apps/agent/src/` itself; (e) the graph map `docs/graph.md` drawn from code by `pnpm graph`, named in the closing message with the reason there is no Studio (the embed server). The plan or scaffold also has suggestions: starters and follow-ups from the tool list, from a separate agent with no thread store, never the chat agent as provider. A run that stops at a blocker (missing Node, key or git, or denied commands) before writing files PASSES when its defaults card or plan states, in any wording, the substance of (a), (b) and (c): a prompt in four parts with a per-run context part, PII redaction on by default (trace masking on), and a seeded baseline eval dataset. Everything else in (a)–(e) is owed by the scaffold and is not required at a blocker: the canary, the case list, schema validation, lint and the graph map.
FAIL if the prompt has a scripted greeting line, PII redaction on this LangChain agent is off by default (Mastra's being off is correct and not a failure), or a single `smoke.eval.ts` or one smoke case is the only eval. Only when files were scaffolded, FAIL also if lint covers only the web code or the closing message gives no graph UI; a blocker report that wrote no files is never failed for missing lint output or a missing graph map.
