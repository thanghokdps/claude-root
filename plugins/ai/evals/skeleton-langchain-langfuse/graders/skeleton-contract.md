The skeleton contract (`agent-architect` `skeleton.md` § 4–6) applies to every empty-chatbot scaffold, whatever the stack.

PASS if the plan or scaffold names all of: (a) a system prompt in four sections — OVERVIEW, RESPONSE, OUT OF SCOPE, CONTEXT — with CONTEXT appended per run from the trusted context (date, caller id) and a canary line for the leak eval; (b) `PII_REDACTION` off by default with trace masking on; (c) `evals/datasets/baseline.jsonl` seeded with four cases (greeting, refusal of data or action, unsure, prompt leak) and schema-validated before the run; (d) ESLint with `@typescript-eslint/no-deprecated` run on the agent folder itself; (e) the Studio URL the dev command prints (`langgraph dev` → LangGraph Studio, `mastra dev` → `http://localhost:4111`) in the closing message. A run that stops at a blocker (missing Node, key or git, or denied commands) before writing files PASSES when its defaults card or plan states, in any wording, the substance of (a), (b) and (c): a prompt in four parts with a per-run context part, PII redaction off by default (trace masking on), and a baseline eval dataset of four cases. The canary, schema validation, (d) and (e) are owed by the scaffold and are not required at a blocker.
FAIL if the prompt has a scripted greeting line, PII redaction is on by default, or a single `smoke.eval.ts` or one smoke case is the only eval. Only when files were scaffolded, FAIL also if lint covers only the web code or the closing message gives no graph UI; a blocker report that wrote no files is never failed for missing lint output or a missing Studio URL.
