## Never copy

Demo pages and showcase data (`showcase.json`, `welcome.ts` seeds, the Dojo's demo agents, workflows and `src/pages/*`), lockfiles (the scaffold resolves its own), `@ts-expect-error` workarounds in the reference, `cors: { origin: '*' }`, the Dojo's browser-side `client.listMemoryThreads({ resourceId })` (the thread routes are `rules/chat-threads.md`), any hard-coded agent id that is not the card's, and the deprecated imports CopilotKit's examples still carry: `LangGraphAgent` / `LangGraphHttpAgent` from `@copilotkit/runtime/langgraph` (v1, `@deprecated Since 1.68.2`; use `@ag-ui/langgraph`), `handle` from `hono/vercel` (use `createCopilotRuntimeHandler`, see R4), and `CopilotKit` from the `@copilotkit/react-core` root, which R3's pages import (v1, `@deprecated Since 1.68.2` at 1.83.0; use `@copilotkit/react-core/v2`). A reference's deprecated line is a defect in the scaffold, whatever the vendor does.

## Procedure (Step 4.0)

1. Resolve the row's default-branch HEAD now, with GitHub MCP `get_file_contents` or `gh api repos/<o>/<r>/commits/HEAD`, and read the core tree at that SHA. Never rebuild a tree from memory.
2. Repo archived, moved, or the path is gone → search the org (`search_repositories org:<o>`), show what was found, and choose the replacement with the user. Do not guess.
3. Mirror the folder layout, file names and entry points. Write every file yourself, under the kit rules (env schema, identity, tests at Q-T, exact pins). Never copy a whole file.
4. Conflicts: on layout and naming the reference wins. On identity, pins, test location and tracing the kit wins. Record each difference in the ADR's Decisions.
5. Write `Reference: <repo>@<sha> · <path>` on the ADR card.
