What changes for a team

    
Claude Code writes code fast. Left alone it also skips the plan, commits to main, says "tests pass" without running them, and forgets everything when the session ends. The kit gives Claude the process a senior engineer follows and makes the non-negotiable steps impossible to skip.

    

      
👔 If you manage the team
AI-written code becomes safer to accept. Every shortcut shows up as a blocked step with a reason, not as a surprise in production. One install command gives every machine the same process.

      
🧑‍💻 If you are a senior engineer
A marketplace of plugins with declared dependencies, routing tests that run free on every change, hooks that exit 0 or 2, and every design decision written down. Opus plans and reviews; cheaper models type.

      
📋 If you are a PM or QA
Describe the feature or the bug in plain words, in any language. The plan, the slices, the evidence and the PR description come back in a shape you can read and challenge.

      
🤖 If you build AI assistants
The ai pack takes a chatbot from one sentence to a scaffolded, traced and evaluated CopilotKit + LangGraph / Mastra app, asking the product questions before any technology.

Start in three steps

    
No configuration. Install once, open your repo, say what you want. The kit reads the repo and turns on the packs it needs.

    

      
1
Install
Inside Claude Code, add the marketplace and install the process kit. Reload.
/plugin marketplace add thanghokdps/claude-root
/plugin install harness@harness
/reload-plugins

      
2
Open your repo
On the first session the repo-profile hook reads your manifests and prints the roles it turned on. They load from the next session.
REPO PROFILE: Next.js, Prisma.
Roles: frontend, backend, devops.
Prefer: features across roles → /feature …

      
3

Engineers

    
/feature is the supervisor: it writes the plan, then dispatches each slice to the engineer of the pack that owns it, on the cheaper model. You never call a role by hand. A slice belongs to the pack of the contract it implements, not the language it is written in.

    

      
backend-engineerbackend
Tables, queries, contract, endpoint, third-party API. Owner-scoped queries, a route matrix of 200 · 400 · 401 · 404.
/db-change/api-endpoint/api-client

      
frontend-engineerfrontend
A web screen from a fixture: every state, primitives built once, Testing Library, checked in the browser at each viewport.
/ui-feature/design-ui

      
mobile-engineermobile
A React Native / Expo screen: navigation, per-platform state, verified on the iOS Simulator or Android emulator.
/mobile-feature

      
devops-engineerdevops
One CI, container or infrastructure change: plan → review → apply when you agree → verify, rollback ready. Production applies stay a person's.
/pipeline/container/infra-change

      
ai-engineerai
Tool, graph, HITL, prompt and the chat surface on CopilotKit · AG-UI with Mastra, LangChainJS or LangGraph, traced and evaluated.
/agent-architect/agent-tool/agent-frontend+9

      
supervisordev · Opus
Plans, chooses the lane, briefs each engineer so nothing is left to decide, reviews every diff before it is integrated, then opens the PR.
/feature/ticket/fix-bug

    

  


  

    
Hooks

    
The checks that must happen, not just be remembered. Gates live in the process plugins, never in a pack, so they hold before a pack is enabled. Hooks exit 0 or 2 and never crash the session.

    

      
branch-guardcore
No commit or push to main or an environment branch from a session; work goes through a branch and a PR.

      
secret-guardcore
.env*, keys and service-account files are never read, printed or edited; Claude asks you for the value.

      
test-lockdev
The test that reproduces a bug is locked while the fix is written; a fix cannot "pass" by editing the test.

      
ticket-gatedev
A ticket's commit waits for the skills its plan names; its PR waits for /verify-done and /review-checklist.

      
release-gateship
A production eas build / submit / update ships only the exact commit of a release/<version> PR approved by someone else.

      
infra-gateship
A production terraform apply, kubectl apply or helm upgrade is run by a person, never from a session; non-production asks first.

    

  


  

    
Packs

    
Process plugins are always on and stack-free. Role packs share one shape, one <role>-engineer agent, deliverable-named skills, stack rules read on demand, no hooks, and are turned on per repo by core's repo-profile hook from what the repo contains. Click a plugin to read its README.
